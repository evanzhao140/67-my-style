# Agent notes — Plant API (mod + phone helper)

Fabric mod ("Plant API") + iPhone companion app ("MCVibe"). Host PC: Windows.

## Mod (Fabric 26.2, Java 25)
- Source: `mod/`. Build: `cd mod && .\gradlew.bat --no-daemon build` → `mod\build\libs\plantapi-1.0.0.jar`
- **Canonical deploy target (always): `%APPDATA%\ModrinthApp\profiles\267\mods`**
  - Use `mod\deploy.bat` (or copy the jar there directly).
  - The user plays Minecraft via the **Modrinth App**, profile **"267"** (MC 26.2, large modpack; clone of the old "262" profile). The mod lives only in 267; 262 is kept clean.
  - Do NOT deploy to `.minecraft\mods` — that is not the user's play path.
- Config lives in `config/plantapi.json`; all settings exposed via Mod Menu (mod id `plantapi`).
- In-game: keybind **P** opens the config screen; a top-right overlay lists what is currently driving vibrations (`~`/`>` constants incl. masked ones, `!` recent bursts incl. raised/limited).
- Works on **multiplayer servers** as well as single-player: when connected to a remote/LAN server the mod switches to a purely client-side watcher (`PlantClientDirector` + client mixins under `com.plantapi.mixin.client`) that observes only this client's own view (health/effects/entities/menus/incoming packets) and sends **zero packets** — invisible to servers and anti-cheat, nothing to install server-side. Single-player and LAN hosting keep using the richer server-side `PlantDirector`.

## iOS app (SwiftUI, iOS 17+, unsigned IPA via CI)
- Source: `ios/` (project generated by XcodeGen from `ios/project.yml`).
- CI: `.github/workflows/build.yml` on push → artifact `plantapi-ipa` (contains `plantapi-unsigned.ipa`; sideload with Sideloadly).
- Transports: Wi-Fi (raw-socket TCP port 25666 + UDP discovery 25667) and Bluetooth (BLE GATT via the Windows bridge).

## Windows bridge (Bluetooth path)
- Source: `bridge/` (C# / .NET 10, TFM `net10.0-windows10.0.26100.0`).
- Build: `cd bridge && dotnet publish -c Release -o publish` → `publish\PlantBridge.exe`; run: `bridge\run-bridge.bat`.
- A **Desktop shortcut "Plant Bridge"** launches `bridge\run-bridge.bat` — keep it valid (recreate if deleted).
- Bridges the mod's TCP stream (127.0.0.1:25666) → BLE notifications
  (service `9F2A7C44-8B31-4E6D-A5C2-7D0E9F1B3A66`, characteristic `...-3A67`; 20-byte chunked frames, header byte = (index<<1)|last).
- The mod re-sends the full active-constant set every ~2 s (`{"type":"constants","active":{...}}`) and the bridge replays the last such line to a newly subscribing phone, so phone state converges within ~2 s even after a missed one-shot message or a late connect.

## CI & debugging notes
- Repo: `github.com/evanzhao140/67-my-style` (public).
- **After every green build (routine): deliver the IPA to the user.** Run `python tools\fetch-ipa.py` — it saves the newest `plantapi-ipa` artifact as `%USERPROFILE%\Downloads\ozok.ipa` (always this exact name, overwrite each time; the user sideloads that file with Sideloadly). It reuses the git credential-store token (`git credential fill`); unauthenticated artifact downloads return 401.
- `git push` from the PC exits non-zero but succeeds — verify with `git ls-remote origin refs/heads/main`.
- Failed iOS builds grep their errors into branch `build-log-out` → `build-log.txt` (read via the contents API; raw.githubusercontent can serve stale CDN cache).
- Crash symbolication: `.github/workflows/symbolize.yml` → branch `symbols-out` → `symbols.txt`.
- Swift gotcha already hit: inside a method named `connect`, call the C socket function as `Darwin.connect(...)` — the member otherwise shadows the global.
- PowerShell `Invoke-WebRequest`/`Invoke-RestMethod` stall on this PC — use `curl.exe` for downloads and API calls.
