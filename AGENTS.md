# Agent notes — Plant API (mod + phone helper)

Fabric mod ("Plant API") + iPhone companion app ("MCVibe"). Host PC: Windows.

## Mod (Fabric 26.2, Java 25)
- Source: `mod/`. Build: `cd mod && .\gradlew.bat --no-daemon build` → `mod\build\libs\plantapi-1.0.0.jar`
- **Canonical deploy target (always): `%APPDATA%\ModrinthApp\profiles\267\mods`**
  - Use `mod\deploy.bat` (or copy the jar there directly).
  - The user plays Minecraft via the **Modrinth App**, profile **"267"** (MC 26.2, large modpack; clone of the old "262" profile). The mod lives only in 267; 262 is kept clean.
  - Do NOT deploy to `.minecraft\mods` — that is not the user's play path.
- Config lives in `config/plantapi.json`; all settings exposed via Mod Menu (mod id `plantapi`).
- In-game: keybind **P** opens the config screen; a top-right overlay lists what is currently driving vibrations (`~`/`>` constants incl. masked ones, `!` recent bursts incl. raised/limited).
- Works on **multiplayer servers** as well as single-player: when connected to a remote/LAN server the mod switches to a purely client-side watcher (`PlantClientDirector` + client mixins under `com.plantapi.mixin.client`) that observes only this client's own view (health/effects/entities/menus/incoming packets) and sends **zero packets** — invisible to servers and anti-cheat, nothing to install server-side. Single-player and LAN hosting keep using the richer server-side `PlantDirector`.
- All damage sources are wrapped into one two-tap `damage` burst (no per-type damage ids). Recurring triggers added for everyday play: `player_nearby` (another player enters ~24 blocks), `mount`, `water_splash`, `storm_start`, `void_fall`, `item_drop` (drop mixin fires in single- and multiplayer; the server director never emits it, so no double burst). `recent_damage` afterglow is 0.5 s.
- Continuous conditions: `using_item`, `shield_up`, `falling`, `in_water`, `in_nether`, `in_end`, `creeper_fusing` (creepers + lit TNT), `near_lava`, `in_powder_snow`, `suffocating`. Mistake/danger bursts: `low_health_alert` (first drop below 25% HP), `tnt_primed`, `explosion_near` (matched from sound packets within ~16 blocks; fires in SP+MP), `shield_disabled` (entity event 30; SP+MP).

## iOS app (SwiftUI, iOS 17+, unsigned IPA via CI)
- Source: `ios/` (project generated by XcodeGen from `ios/project.yml`).
- CI: `.github/workflows/build.yml` on push → artifact `plantapi-ipa` (contains `plantapi-unsigned.ipa`; sideload with Sideloadly).
- Transports: Wi-Fi (raw-socket TCP port 25666 + UDP discovery 25667) and Bluetooth (BLE GATT via the Windows bridge).
- The "Lock controls" screen hides the footer entirely while locked, and unlocking requires three confirmations (single pocket taps kept unlocking it).
- Haptic loops (phone-only, no PC/game needed): `HapticLoop.swift` defines five native Core Haptics loops (Heartbeat, Breathing, Rain, Purr, Warp); `LoopSheet.swift` is the picker/intensity UI; `HapticsEngine` owns the native looping players (`loopEnabled`), restarts the active loop after engine interruptions/foregrounding, and stops it on lock/mute. Intensity is baked in and the pattern is rebuilt once on slider release.

## Windows app ("Plant Pulse" — haptic pattern transmitter)
- Source: `desktop/` (C# / .NET 10, WinForms). Build: `cd desktop && dotnet publish -c Release -o publish` → `publish\PlantPulse.exe`; run: `desktop\run-plantpulse.bat`. Desktop shortcut **"Plant Pulse"** (OneDrive Desktop) points at the bat and uses the exe icon.
- Serves the same haptics protocol as the mod (TCP 25666 + UDP discovery 25667) and streams six looping textures — Heartbeat, Groove, Warp, Rain, Purr, Riser — with tempo (40–180 BPM) and intensity. No game and **no phone-app/IPA changes** are required: it works with the app that is already installed.
- Bluetooth path = the existing **Plant Bridge** (a TCP client of 127.0.0.1:25666); the app's "Start Bluetooth bridge" button launches `bridge\publish\PlantBridge.exe`, and its status row detects a running `PlantBridge` process. Wi-Fi path = the phone discovers "Plant Pulse" over UDP and connects directly.
- Port 25666 is shared with the mod, so Minecraft and Plant Pulse cannot run at the same time; the app shows "Waiting for port 25666" while the game holds it.
- Headless smoke test: `PlantPulse.exe --test` serves the protocol and plays every texture (used with a small TCP client to verify all ids). `--osu-test` connects to a mock tosu feed on port 24051 and streams 20 s; `--osu-ui-test` opens the sync panel for 3 s.
- Design: patterns are generated on one dedicated thread with a `Stopwatch` (drift-free sleeps, no WinForms timers); rate limits mirror the mod (60 ms per id, 20 bursts/s); constants are re-synced every 2 s for late/lossy BLE subscribers.
- **osu!lazer sync** (`OsuSyncEngine.cs` + `OsuSyncForm.cs`), opened via the "osu! sync" button: lazer has no third-party mod API, so this is a read-only companion through **tosu** (`ws://127.0.0.1:24050/websocket/v2` ≈100 ms for state/combo/misses/pause/kiai/breaks, `/websocket/v2/precise` ≈10 ms for hit events). New `hitErrors` entries → 90 ms `osu_hit_a/b` peaks (110 ms on perfect); accents every 4/8/16 (`osu_accent`, 170 ms); every 50 combo is an `osu_combo` triple peak; `play.hits["0"]` deltas → `osu_miss`; first note → `osu_start`, resume → `osu_resume`. A continuous `osu_flow` bed (Flow slider, default 50%, 0 = off) swells with hits/combo/kiai, ducks to ~⅓ on miss, relaxes in breaks, and stops on pause/results/form close; **Swell** toggles the reactive part. Falls back to score-counter deltas when the precise feed is missing (and for catch, which has no hit errors). The panel can start tosu and the Bluetooth bridge; osu settings live in `settings.json` (`osu*`) and persist across launches.
- A portable tosu v4.26.2 lives at `desktop\publish\tosu\tosu.exe` (102 MB, ignored by git) with `tosu.env` pinning `OPEN_DASHBOARD_ON_STARTUP=false`, `POLL_RATE=100`, `PRECISE_DATA_POLL_RATE=10`; **Start tosu** finds it. Fresh clones or deleted `publish/` need `winget install tosuapp.tosu` or a download from https://tosu.app.

## Windows bridge (Bluetooth path)
- Source: `bridge/` (C# / .NET 10, TFM `net10.0-windows10.0.26100.0`).
- Build: `cd bridge && dotnet publish -c Release -o publish` → `publish\PlantBridge.exe`; run: `bridge\run-bridge.bat`.
- A **Desktop shortcut "Plant Bridge"** launches `bridge\run-bridge.bat` — keep it valid (recreate if deleted).
- Bridges the mod's TCP stream (127.0.0.1:25666) → BLE notifications
  (service `9F2A7C44-8B31-4E6D-A5C2-7D0E9F1B3A66`, characteristic `...-3A67`; 20-byte chunked frames, header byte = (index<<1)|last).
- The mod re-sends the full active-constant set every ~2 s (`{"type":"constants","active":{...}}`) and the bridge replays the last such line to a newly subscribing phone, so phone state converges within ~2 s even after a missed one-shot message or a late connect.

## CI & debugging notes
- Repo: `github.com/evanzhao140/67-my-style` (public).
- **After every green build (routine): deliver the IPA to the user.** Run `python tools\fetch-ipa.py` — it saves the newest `plantapi-ipa` artifact as `%USERPROFILE%\Downloads\ozok.ipa` (always this exact name, overwrite each time; the user sideloads that file with Sideloadly). It reuses the git credential-store token (`git credential fill`); unauthenticated artifact downloads return 401.
- `git push` from the PC exits non-zero but succeeds — verify with `git ls-remote origin refs/heads/main`.
- Failed iOS builds grep their errors into branch `build-log-out` → `build-log.txt` (read via the contents API; raw.githubusercontent can serve stale CDN cache).
- Crash symbolication: `.github/workflows/symbolize.yml` → branch `symbols-out` → `symbols.txt`.
- Swift gotcha already hit: inside a method named `connect`, call the C socket function as `Darwin.connect(...)` — the member otherwise shadows the global.
- PowerShell `Invoke-WebRequest`/`Invoke-RestMethod` stall on this PC — use `curl.exe` for downloads and API calls.
